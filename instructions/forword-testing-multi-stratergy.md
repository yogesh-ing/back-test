# Comprehensive Product Requirements Document (PRD)
## Module: Multi-Strategy Multi-Instrument Forward Testing Engine (Portfolio Command Center)

---

## 1. Executive Summary & Vision

The **Forward Testing Engine** transitions from a single-strategy simulator into an **Institutional Portfolio Command Center**. Real quantitative desks never risk capital on a single strategy or single instrument; true risk-adjusted alpha is generated by running a **diversified portfolio of uncorrelated strategies** across diverse assets and timeframes.

This module introduces a two-tiered container architecture:
1. **`StrategyRunner` (Execution Unit)**: An isolated container executing a specific strategy against either a **Single Instrument** (e.g., `BTC/USD`) or a **Dynamic Symbol Universe/Pool** (e.g., `NIFTY 50` or `Top 20 Crypto`).
2. **`PortfolioManager` (Orchestration Engine)**: A centralized control tower managing up to **50+ active `StrategyRunner` instances**, aggregating portfolio-wide PnL, enforcing global risk limits (circuit breakers), and preventing cross-strategy order collisions.

## 2. Key Architecture Concepts

### 2.1 The Two-Layer Paradigm

To ensure scalability from 1 strategy to 50+ concurrent strategies without codebase refactoring, the engine is designed in two strict layers:

```python
# Layer 1: Isolated Execution Worker
class StrategyRunner:
    instance_id: str             # UUID v4 identifier
    name: str                    # Instance alias (e.g. "RSI-BTC-4H")
    strategy_class: BaseStrategy # Concrete strategy class
    target_type: str             # "SINGLE_SYMBOL" or "SYMBOL_UNIVERSE"
    symbols: List[str]           # Single list ["BTC/USD"] or Pool ["TCS", "INFY", "RELIANCE", ...]
    timeframe: str               # Execution timeframe (e.g. "1m", "15m", "1h", "4h", "1d")
    allocated_capital: float     # Ring-fenced capital limit
    current_positions: Dict      # Active open positions owned ONLY by this instance
    metrics: InstanceMetrics     # Instance PnL, Win Rate, Drawdown

# Layer 2: Master Portfolio Orchestrator
class PortfolioManager:
    active_runners: Dict[str, StrategyRunner] # Map of instance_id -> StrategyRunner
    global_portfolio_limit: GlobalRiskConfig   # Portfolio-level circuit breakers
    broker_gateway: BaseBroker                 # Active broker session interface
```

### 2.2 Target Instrument Types: Single Symbol vs. Symbol Universe (Pool)

Strategies operate under two target modes:
1. **Single Symbol Mode**: Strategy runs against one explicit ticker (e.g., `BTC/USD` or `RELIANCE`). Ideal for high-frequency or mean-reversing algorithms.
2. **Symbol Universe / Pool Mode**: Strategy evaluates a dynamic basket of stocks/crypto assets (e.g., `NIFTY_50_POOL` or `TOP_10_ALTCOINS`). 
   * **Swing Strategy Support**: The `StrategyRunner` runs signals across all symbols in the basket on candle close, ranks opportunities, and executes entries on the top $K$ candidates up to its allocated capital limit.

### 2.3 Capital Allocation & Isolated Bucket Model (V1)

To prevent a rogue strategy from draining total account equity:
* **Isolated Capital Buckets**: Every `StrategyRunner` is assigned an explicit `allocated_capital` quota (e.g., $100,000).
* **Position Sizing Boundary**: Max risk and order size for an instance are strictly bounded by its isolated allocation.
* **PnL Isolation**: If Instance #1 loses $5,000, its available capital shrinks to $95,000. Instance #2's capital is completely untouched.

## 3. Global Risk Management & Circuit Breakers

The `PortfolioManager` operates an independent background supervisor that runs on every tick/event update, overriding individual strategy decisions if portfolio-wide safety limits are breached.

```
                       Portfolio Risk Supervisor Loop
                                      │
              ┌───────────────────────┴───────────────────────┐
              ▼                                               ▼
   Instance-Level Checks                          Portfolio-Level Checks
 ├── Instance Max Drawdown (%)                  ├── Total Portfolio Max Drawdown (%)
 ├── Instance Daily Loss Cap ($)                ├── Combined Portfolio Daily Loss ($)
 └── Instance Max Position Limit                └── Portfolio Leverage / Margin Cap
              │                                               │
              └───────────────────────┬───────────────────────┘
                                      │
                                      ▼
                        Breach Detected? ───► YES ──► TRIGGER CIRCUIT BREAKER
                                │                       ├── Pause New Orders
                                No                      ├── Option to Flatten Positions
                                ▼                       └── Emit Critical Alert
                          Allow System Operation
```

### Circuit Breaker Rules (V1)
1. **Global Daily Loss Limit**: If sum of realized + unrealized PnL across ALL runners drops below `-$DAILY_LIMIT` (e.g., -$10,000), `PortfolioManager` triggers a global halt:
   * **Mode A (Pause & Hold)**: Stops all new order entries across all strategies; lets active positions hit their SL/TP.
   * **Mode B (Nuclear / Emergency Flatten)**: Cancels all open orders and sends market exit orders for all open positions across all runners.
2. **Global Drawdown Breach**: Halts the engine if aggregate portfolio equity falls below a defined peak-to-trough threshold (e.g., 10% total drawdown).
3. **Correlation Risk Warning (V1 Telemetry)**: If 3 or more runners hold LONG positions in highly correlated instruments (e.g., `BTC/USD`, `ETH/USD`, `SOL/USD`), the system flags a **High Concentration Warning** on the dashboard.

## 5. System Specifications & Performance Rules

1. **Threading & Concurrency Model**:
   * Each `StrategyRunner` operates as an isolated worker within a managed `ThreadPoolExecutor` or `AsyncIO` event loop inside the Flask/Python backend process.
   * Memory footprint per instance must stay under **15 MB RAM** by maintaining lightweight rolling candle buffers (max 500 bars in memory per symbol).
2. **Order Tagging Schema**:
   * Every order emitted by any instance is tagged with metadata:
     `client_order_id = "PRT-{instance_id}-{timestamp_ms}"`
   * Prevents order collision and allows the execution layer to route fills back to the correct `StrategyRunner`.
3. **WebSockets Push Updates**:
   * Dashboard uses Server-Sent Events (SSE) or WebSockets (`/ws/portfolio`) to broadcast state updates every 1 second, avoiding UI polling lag when running 50+ active runners.

## 6. Scope Boundaries

### In-Scope (V1 Architecture)
1. `StrategyRunner` container supporting isolated capital, PnL tracking, and execution loop.
2. Dual Target Mode support: `SINGLE_SYMBOL` and `SYMBOL_UNIVERSE` (Pool/Basket).
3. `PortfolioManager` orchestration layer capable of running 50+ strategy instances simultaneously.
4. Order Tagging Ledger ensuring zero cross-contamination of trades.
5. Global Portfolio Circuit Breaker (Max Portfolio Daily Loss limit & Global Pause/Flatten).
6. Multi-Instance High-Density Table UI + Instance Deep-Dive Modal.
7. Bulk Instance Control (`Pause All`, `Resume All`, `Stop All`).

### Deferred (V2 Portfolio Ops)
1. Volatility-weighted automated capital rebalancing across active runners.
2. Shared capital liquidity pool model with dynamic priority execution queues.
3. Real-time correlation matrix heatmaps for portfolio assets.
